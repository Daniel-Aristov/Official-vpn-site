# Инструкции для ИИ-агентов

Этот файл действует для всего репозитория Official VPN Site. Актуальные указания пользователя имеют приоритет: если задача меняет описанное ниже поведение, реализуйте новое требование и обновите соответствующую документацию.

## Контекст проекта

Адаптивный сайт OFL VPS по макетам Figma. Стек: React, TypeScript, Vite, Tailwind CSS 4 и React Router. Интерфейс и общение с пользователем — на русском языке; имена компонентов, функций и переменных — на английском.

Основные маршруты: `/`, `/subscribe`, `/subscribe/success`, `/subscribe/error`. Маршрутизация задаётся в `src/App.tsx`.

SEO: в `.env` используется одна переменная `VITE_SITE_URL=https://oflvpn.com`. Метаданные находятся в `src/lib/seo.ts`, обновляются в `App.tsx` и подставляются в HTML существующих маршрутов через `vite.config.ts`; там же генерируются robots и sitemap. Индексируется главная; оформление, результаты оплаты и проекты юридических документов имеют `noindex, follow`. Отдельной SSR-сборки и дополнительных SEO-страниц нет. После смены домена нужна новая сборка.

Юридические страницы: `/offer`, `/data-processing`, `/privacy`. Тексты и незаполненные реквизиты находятся в `src/data/legalDocuments.ts`; не выдумывайте сведения о владельце и инфраструктуре. По указанию пользователя на страницах документов не отображаются дата редакции, плашка о проекте и нижний список ссылок на документы. Все три ссылки доступны в футере главной. Текст чекбокса при оплате: «Я соглашаюсь с офертой и политикой конфиденциальности»; обе ссылки открываются в новой вкладке, чтобы сохранить введённые данные.

Установка зависимостей: `npm ci`. Локальная разработка: `npm run dev`. Просмотр готовой сборки: `npm run preview`.

## Работа с кодом

- Перед изменениями изучите относящиеся к задаче компоненты, `README.md` и команды в `package.json`. Проверяйте фактическое состояние файлов: пользователь может редактировать проект параллельно.
- Вносите изменения в рамках задачи. Сохраняйте чужие правки; не выполняйте попутный рефакторинг и массовое форматирование.
- Используйте функциональные React-компоненты, типизированные props и хуки. Переиспользуйте существующие компоненты вместо создания их копий.
- Секции страниц и самостоятельные части интерфейса размещайте в `src/components`, общие элементы — в `src/components/UI`, компоненты подписки — в `src/components/subscription`, TSX-иконки — в `src/components/icons`.
- Общую логику размещайте в `src/hooks`, данные — в `src/data`, вспомогательные функции — в `src/lib`. Для импортов из `src` используйте алиас `@/`.
- Тарифы и пути оформления берите из `src/data/subscriptionPlans.ts`, Telegram поддержки — из `src/data/supportContacts.ts`. Не дублируйте эти значения в компонентах.
- Соблюдайте `.prettierrc`: два пробела, одинарные кавычки, без точек с запятой. Новые зависимости добавляйте только при необходимости; изменения зависимостей должны сопровождаться актуальным lock-файлом.
- Не редактируйте вручную `dist` и `node_modules`. Не добавляйте в репозиторий временные скриншоты, логи и секреты.

## Стили и ресурсы

- Стили компонентов пишите на Tailwind CSS. Цвета интерфейса выносите в переменные `@theme` в `src/styles/index.css` и используйте существующие токены.
- Учитывайте синтаксис Tailwind CSS 4: классы `translate-*` и `rotate-*` используют отдельные CSS-свойства. В анимациях указывайте соответствующие свойства перехода.
- Не меняйте `AppBackground` и фоновые свечения без задачи на изменение фона.
- Для внешних отступов главной страницы используется порог `min-[1000px]`. От этой ширины внешние `px-4` у секций убраны, кроме блоков тарифов, подключения и завершающего предложения: у них сохраняются `px-4` и добавляется скругление 16 px. Остальные адаптивные классы, например `md:grid-cols-2`, сохраняйте по месту.
- Логотип переиспользуйте через `BrandLogo`: общая иконка и текстовая подпись, а не изображение всего названия.
- Изображения и SVG храните локально в `public/assets`, шрифты — в `public/fonts`. Не оставляйте временные ссылки Figma в коде. Для сторонних ресурсов сохраняйте лицензии и единый визуальный стиль; для флагов уже используется набор flag-icons.
- При работе по макету сверяйте размеры, отступы, типографику и состояния интерфейса. Проверяйте мобильную и широкую версии.

## Поведение интерфейса

Сохраняйте следующие договорённости, если задача явно не требует их изменить:

- Верхняя шапка раскрывает меню вниз, закреплённая нижняя — вверх. Перенос шапки при скролле происходит без анимации и закрывает открытое меню в обоих направлениях. Раскрытие по бургеру остаётся плавным: открытие 250 мс, закрытие 200 мс.
- Пункты меню ведут к секциям `#features`, `#pricing`, `#servers`, `#connection`, `#faq`. Кнопка «Купить» в шапке ведёт к `#pricing`. Используйте `useAnchorScroll` для быстрой плавной прокрутки и переноса фокуса к целевому блоку.
- Лента стран движется влево без скачка на стыке, останавливается при наведении и фокусе. Служебная копия списка скрывается от скринридеров. При уменьшенном движении доступна ручная прокрутка.
- Выпадающий выбор оплаты перекрывает следующий блок без сдвига страницы. Выбранный способ находится сверху и не повторяется в списке. Список закрывается после выбора, по Escape и при взаимодействии снаружи.
- FAQ на главной и странице результата оплаты используют общую карточку `src/components/UI/FaqItem.tsx` и одинаковое оформление. Номера остаются только у вопросов, блок вопроса с номером выравнивается по вертикальному центру кнопки раскрытия.
- Окно исправления почты открывается от нижнего края на всю ширину, имеет только верхние скругления и плавно закрывается вниз. Поле ввода не получает автоматический фокус.
- После сохранения нового адреса почты сверху экрана появляется уведомление с этим адресом. Оно закрывается по крестику или автоматически через 3 секунды; повторная смена почты запускает таймер заново.
- После копирования иконка меняется на галочку на 3 секунды. Повторная отправка письма блокируется на 40 секунд; у заблокированной кнопки нет анимации нажатия.
- Почтовые ссылки используют `mailto:`. Внешние ссылки поддержки открываются через `target="_blank"` с `rel="noopener noreferrer"`.

## Подписка и доступность

- Сейчас оплата и отправка писем реализованы как демо, без реальных списаний и отправки. СБП ведёт на успешный результат, оплата картой — на ошибку; `demoResult=error` также принудительно показывает ошибку.
- Сохраняйте выбранный тариф через параметр `plan`, а данные заказа — через существующую логику `src/lib/demoSubscription.ts` и состояние маршрута. Почта в результате должна соответствовать введённой на предыдущем шаге.
- Для кнопок-ссылок переиспользуйте `ActionLink`. Действия с `role="button"` должны работать с клавиатуры; заблокированные действия должны блокировать и мышь, и клавиатуру.
- Поддерживайте `aria-expanded`, связи заголовков и содержимого, закрытие по Escape и осмысленное управление фокусом. Не устанавливайте `aria-hidden` на сфокусированный элемент или его предка; для неактивной навигации используйте `inert`.
- Соблюдайте `prefers-reduced-motion`, очищайте таймеры, обработчики событий, наблюдатели и `requestAnimationFrame` при завершении работы компонентов.

## Проверка изменений

- Для изменений кода выполняйте `npm run build` и `npm run lint`. Форматируйте только затронутые файлы через `npm exec prettier -- --write <пути>`.
- Для изменений интерфейса проверьте затронутые страницы в браузере: узкий экран, широкий экран и границу 999/1000 px, если меняется адаптивность.
- Для изменений меню и форм проверяйте открытие, закрытие, клавиатуру, фокус, отсутствие горизонтального переполнения и предупреждений консоли. У анимаций проверяйте промежуточные состояния, а не только итоговый кадр.
- Отдельного скрипта `npm test` сейчас нет. Добавляйте автоматические тесты для существенной логики и регрессий, если это оправдано задачей; для простых визуальных правок достаточно целевой проверки в браузере.
- Изменения только документации не требуют сборки приложения. Сверяйте описания команд и поведения с исходниками.
- В итоговом ответе кратко укажите, что изменено, что проверено и какие проверки не удалось выполнить. Не заявляйте об успешных проверках без фактического запуска.
